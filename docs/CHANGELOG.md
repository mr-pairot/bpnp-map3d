## 3. ระบบเวอร์ชันและการออกเวอร์ชัน

### เลข 3 ตัว
| ตัวแปร | อยู่ที่ | ใครเปลี่ยน | ผล |
|---|---|---|---|
| `version` + `changelog` | `version.json` | **ผู้พัฒนา (แก้เองที่เดียว)** | เลขที่ผู้ใช้เห็น + แจ้งเตือน/ปุ่มอัปเดต |
| `build` / `APP_VERSION` | `version.json` / `index.html` | Netlify อัตโนมัติ | hash ของ `js/` + `css/` + `sw.js` → แก้โค้ด = ผู้ใช้ได้โค้ดใหม่ |
| `dataVersions` | `version.json` | Netlify อัตโนมัติ | hash รายไฟล์ใน `data/` → โหลดใหม่เฉพาะไฟล์ที่เปลี่ยน |

หน้าต้อนรับแสดง `Version: 2.4.01 (build 876c595b)` (เปิดในเครื่องโดยไม่ผ่าน build จะแสดง `build dev`)

**ใน GitHub ห้ามแก้ `APP_VERSION`, `build`, `dataVersions` เอง** — `index.html` ต้องคงเป็น `'__APP_BUILD__'` และ `"build": ""` ซึ่งถูกต้องแล้ว เพราะ Netlify คำนวณใหม่ทุกครั้งที่ deploy

### รูปแบบเลข version
`MAJOR.MINOR.PATCH` โดยใช้เลข 2 หลักต่อเนื่อง: `2.4.01` → `2.4.02` …
- อัปเดตข้อมูล / แก้เล็กน้อย → เพิ่ม PATCH
- เพิ่มเลเยอร์ / เครื่องมือ → เพิ่ม MINOR (`2.5.01`)
- ปรับระบบครั้งใหญ่ → เพิ่ม MAJOR (`3.0.01`)

### ผู้ใช้ได้ของใหม่เมื่อไร
| สถานะผู้ใช้ | ไม่เปลี่ยน `version` | เปลี่ยน `version` |
|---|---|---|
| เปิดแอปใหม่ (ออนไลน์) | ได้โค้ด/ข้อมูลใหม่ (ไม่มีแจ้งเตือน) | reload อัตโนมัติ 1 รอบ แล้วได้ของใหม่ |
| เปิดแอปค้างไว้ | ใช้ของเดิมจนกว่าจะเปิดใหม่ | ขึ้นปุ่มอัปเดต + changelog (ตรวจทุก 10 นาที และเมื่อกลับมาที่แอป) |
| ออฟไลน์ | ใช้ของเดิมในเครื่อง | ใช้ของเดิมในเครื่อง |

"เปิดใหม่" = ปัดปิดแอปแล้วเปิด หรือรีเฟรช — การสลับแอปไปมาไม่นับ (โดยเฉพาะ iPhone)

### วิธีออกเวอร์ชัน
| งาน | ต้องทำ |
|---|---|
| อัปเดตข้อมูล ไม่รีบ | แทนที่ไฟล์ใน `data/` → push |
| อัปเดตข้อมูล/โค้ด ต้องการแจ้งผู้ใช้ | + แก้ `version` และ `changelog` ใน `version.json` → push |
| เพิ่มฟีเจอร์ | + เพิ่มรายการใน `history.json` (หน้า "มีอะไรใหม่") |

### ข้อควรระวัง
1. `version.json` พิมพ์ผิดรูปแบบ JSON → deploy ล้มเหลว (เว็บเดิมยังทำงาน) ดูสาเหตุใน Deploy log
2. ถ้าเปลี่ยนไปอัปโหลดแบบลากวาง ต้องรัน `node tools/build.js` เองก่อน
3. เน็ตช้ามาก (version.json ตอบช้ากว่า 3 วินาที) รอบนั้นอาจใช้ข้อมูลเวอร์ชันที่จำไว้ และได้ของใหม่ในการเปิดครั้งถัดไป

## 4. ระบบแคช

| ส่วน | จัดการโดย | กลยุทธ์ |
|---|---|---|
| ไฟล์ข้อมูล `data/*` | `js/dataCache.js` (Cache API) | ตาม `dataVersions`: ตรงกัน → ใช้แคช / เปลี่ยน → โหลดใหม่และลบแคชเก่าของไฟล์นั้น / ออฟไลน์ → ใช้แคชล่าสุด |
| `index.html`, `version.json`, `history.json` | `sw.js` | ถามเซิร์ฟเวอร์ก่อน (ออฟไลน์ใช้ฉบับที่เก็บไว้) |
| JS/CSS ของแอป | `sw.js` | ใช้แคชตาม `?v=build` (build เปลี่ยน → URL เปลี่ยน → โหลดใหม่ และลบของเวอร์ชันเก่า) |
| รูป, Library จาก CDN | `sw.js` | ใช้แคชทันที แล้วอัปเดตเบื้องหลัง |
| Tile แผนที่, API, Google Apps Script | — | ไม่แคช |

รายละเอียดของ `dataCache.js`:
- ครอบ `fetch` และ `omnivore.kml` ให้อัตโนมัติ โค้ดเดิมที่โหลดจาก `data/` ไม่ต้องแก้
- KML เก็บเป็น GeoJSON ที่แปลงแล้ว ครั้งต่อไปไม่ต้องแปลง XML ซ้ำ
- คำขอไฟล์เดียวกันที่เกิดพร้อมกันรวมเป็นคำขอเดียว

**ตรวจแคชใน Console:** `DataCache.report()` (รายการไฟล์ เวอร์ชัน ขนาด) / `DataCache.stats` (จำนวนครั้งที่ใช้แคช) / `APP_VERSION` (เลข build)

"รีเซ็ตระบบ" ในแอปล้างแคชทั้งหมด (รวมข้อมูลเลเยอร์) ตามที่ตั้งใจ

### การตั้งค่าแผนที่ของผู้ใช้ (`js/main.js`)
| ค่า | หน้าที่ | แก้แล้ว |
|---|---|---|
| `SETTINGS_VERSION` | เลขกำกับการตั้งค่าที่บันทึก (เทียบแค่ตรง/ไม่ตรง) | การตั้งค่าของผู้ใช้ทุกคนกลับเป็นค่าเริ่มต้น (`isDefault`) และลบของเก่าออก — **ใช้ตัวนี้เมื่อต้องการรีเซ็ต** |
| `STORAGE_KEY` | ชื่อช่องเก็บการตั้งค่าแผนที่ | รีเซ็ตเหมือนกัน แต่ข้อมูลช่องเดิมค้างในเครื่อง — ไม่แนะนำให้แก้ |
| `LEGEND_STORAGE_KEY` | ชื่อช่องเก็บสถานะย่อ/ขยายกล่อง Legend เวนคืน | กล่อง Legend กลับเป็นสถานะเริ่มต้น |

ควรเปลี่ยน `SETTINGS_VERSION` เมื่อ: เปลี่ยน `isDefault` ของเลเยอร์เดิมแล้วอยากให้ผู้ใช้เดิมเห็น, เปลี่ยนชื่อที่แสดงของเลเยอร์ (ลำดับที่ลากเรียงบันทึกด้วยชื่อ), ปรับแผงเลเยอร์ครั้งใหญ่
ไม่ต้องเปลี่ยนเมื่อ: เพิ่ม/ลบเลเยอร์ (เลเยอร์ใหม่ใช้ `isDefault` เอง), อัปเดตข้อมูล, แก้โค้ดทั่วไป

| `v` (URL หน้าเว็บ) | `2.4.01` | บังคับโหลด index.html ใหม่ตอนแจ้งอัปเดต | `checkUpdate.js` | เมื่อเข้าแอป |
| `v` (ไฟล์ JS/CSS) | `main.js?v=876c595b` | เลข build ของโค้ด | `auth.js` | **ไม่ลบ (จำเป็น)** |

`auth.js` ลบพารามิเตอร์เหล่านี้ด้วย `history.replaceState()` (หน้าไม่โหลดใหม่) URL จึงเหลือ `https://bpnp-map.netlify.app/` และพารามิเตอร์อื่นที่ไม่เกี่ยวข้องยังอยู่ครบ
- **ต้องลบหลัง `liff.init()` เท่านั้น** ไม่เช่นนั้นการล็อกอินล้มเหลว
- **ประโยชน์:** URL สั้น, ไม่เผลอแชร์รหัสล็อกอิน, กัน bookmark/รีเฟรชที่มี `code` เก่าทำให้ LINE แจ้งข้อผิดพลาด

## 6. เว็บทดสอบ (demo)

`https://bpnp-map-demo.netlify.app` — repo, GAS และ Google Sheet แยกจากเว็บหลัก (repo ทั้งคู่เป็น Private)

### หลักการ
GAS ของ demo เป็นผู้ตัดสิน: ผู้ที่ไม่อยู่ใน allowlist ได้คำตอบพร้อม `redirect` → `auth.js` ล้าง session แล้วส่งไป `https://liff.line.me/2007032148-uTzLx8Ed` (LIFF เว็บหลัก) โดยไม่เห็นแผนที่ demo

| ส่วน | สิ่งที่ทำ |
|---|---|
| `Code_demo.gs` | allowlist จาก Script Properties `DEMO_ALLOWED_IDS`; ตรวจ ID Token กับ LINE (ปลอม userId ไม่ได้); ผู้ไม่ได้รับอนุญาตไม่ถูกบันทึกลงแท็บ Users (บันทึกใน UsageLog ว่า `Demo Denied`) |
| `auth.js` | โดเมนที่มี `-demo` → รอ GAS ตอบก่อนแสดงแผนที่; ทำตาม `redirect` เฉพาะ `liff.line.me` และ `bpnp-map.netlify.app`; ID Token หมดอายุ → ล็อกอิน LINE ใหม่ 1 ครั้ง |
| GAS ผู้ใช้ทั่วไป | ไม่ต้องแก้ (ไม่เคยส่ง `redirect`) |

`auth.js` ใช้ไฟล์เดียวกันทั้ง 2 repo **ต่างกันแค่ `AUTH_CONFIG`**:
| | LIFF | GAS |
|---|---|---|
| เว็บหลัก | `2007032148-uTzLx8Ed` | GAS ผู้ใช้ทั่วไป |
| demo | `2007032148-aaRo9Xb1` | GAS demo |

### ตั้งค่า (ครั้งเดียว — ทำก่อนนำ `auth.js` ขึ้น repo demo)
1. LINE Developers → LIFF demo → Scopes ติ๊ก **openid** (และ profile); Endpoint URL = `https://bpnp-map-demo.netlify.app`
2. GAS demo → วางโค้ด `Code_demo.gs`
3. Project Settings → Script Properties → `DEMO_ALLOWED_IDS` = LINE userId ของผู้ทดสอบ (ดูจากคอลัมน์ A แท็บ Users ของ Sheet demo; หลายคนคั่นด้วย `,`)
4. รันฟังก์ชัน `authorizeOnce` 1 ครั้ง → อนุญาตสิทธิ์
5. Deploy → Manage deployments → ✏️ → Version: **New version** → Deploy (URL เดิม)

เพิ่ม/ลบผู้ทดสอบ: แก้ `DEMO_ALLOWED_IDS` ได้ทันที ไม่ต้อง deploy ใหม่

### ข้อจำกัด
ไฟล์ใน `data/` ของเว็บ demo ยังเปิดตรงได้ถ้ารู้ URL (เหมือนเว็บหลัก) ระบบนี้กั้นที่หน้าแอป

## 7. ขั้นตอน deploy และตรวจหลัง deploy

### นำขึ้น GitHub
1. วางไฟล์จากชุด "changed files" ทับของเดิม
2. ลบไฟล์ตามหัวข้อ 2 ("ไฟล์ที่ต้องลบออกจาก GitHub")
3. repo demo: ทำตั้งค่าหัวข้อ 6 ก่อน แล้วแก้ `AUTH_CONFIG` ใน `auth.js` เป็นค่า demo
4. Push

### ตรวจหลัง deploy
1. Netlify → Deploys → log ล่าสุดต้องมี
   ```
   ✔ version : 2.4.01
   ✔ build   : xxxxxxxx (จากโค้ด 76 ไฟล์)
   ✔ dataVersions: 40 ไฟล์
   ```
2. เปิด `https://<เว็บ>/version.json` เห็น `build` และ `dataVersions`; หน้าต้อนรับแสดง `2.4.01 (build …)` ตรงกัน
3. กด **ออกจากระบบ** → ล็อกอินใหม่ด้วย LINE → URL สั้นหลังเข้าแอป
4. กด **รีเซ็ตระบบ** → ต้องถูกถามให้ล็อกอิน LINE ใหม่
5. เปิดผ่าน **ลิงก์ LIFF ในแอป LINE**
6. เปิดแอปครั้งที่ 2 → DevTools → Network ไม่มีการโหลดไฟล์ใน `data/`
7. ปิดเน็ตแล้วเปิดแอป (หลังเคยเปิดออนไลน์อย่างน้อย 2 ครั้ง)
8. เว็บ demo: เปิดด้วยบัญชี LINE อื่น → ถูกส่งไปเว็บหลัก

**ครั้งแรกหลัง deploy:** ผู้ใช้เดิมถูก reload 1 รอบ (เลขเปลี่ยนจาก `v2.3.1020.01a`) และต้องโหลดข้อมูลใหม่ 1 รอบ ความเร็วจะเห็นผลตั้งแต่ครั้งที่ 2
